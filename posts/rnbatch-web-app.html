rnbatch：从杂乱文件夹到整齐项目档案，只差一次确认

让命名真正基于文件内容，让批量操作先有预览、再有确认，最后还能反悔。一个为真实文件整理场景设计的轻量工具。

一个项目刚开始时，文件夹通常还算整齐。几周以后，里面可能已经堆满 IMG_0421.JPG、微信图片_20261018.jpg、最终版_v3_真最终.pptx，再夹杂合同、会议纪要、PDF 和 Excel。文件内容很重要，但名字几乎没有告诉你“它属于哪个项目”。

rnbatch 想解决的不是简单的批量替换字符，而是更靠前的一步：从已有文件里找到可用的命名线索，再安全地整理整批文件。

不是让用户一个个修改文件名，而是把“理解内容 → 命名 → 检查 → 执行”变成一条清晰流程。

一、先读内容，再决定叫什么

传统批量重命名工具擅长加前缀、替换字符串、连续编号，但前提是你已经知道正确的前缀。rnbatch 将正文提取放进命名流程：读取 Word、PPT、Excel、PDF 等文档中的文本，在可用环境下还可借助 OCR 理解图片里的文字。

系统根据内容生成候选关键词及其依据，由人或 AI 来判断哪一个真正代表项目。它不会声称仅凭算法就一定理解文件含义，而是把做判断需要的信息准备好。

二、浏览器里完成整批整理

rnbatch 目前优先发展的形态是 Web App。在浏览器工作流中，用户可选择文件或文件夹，上传到临时工作区，从候选词中选定命名规则，预览结果，确认后执行，并把整理后的文件打包为 ZIP 下载。

上传与临时工作区围绕上传副本组织处理，避免直接改动用户在浏览器里选中的原文件。
文档正文提取从多种办公文档中寻找项目名、机构名等关键词线索，减少人工逐份打开的时间。
命名模板支持关键词、序号、文件类型、原名、日期等变量组合，统一整批文件命名格式。
预览、冲突检查与撤销改动前先看完整映射；对重名、占用和异常情况进行拦截，并保留可撤销的操作路径。

三、安全感，来自“先预览、再执行”

批量改名最让人不安的不是速度慢，而是“点一下就把重要文件改乱了”。因此，rnbatch 把预览做成独立步骤：先列出旧文件名与目标文件名的对应关系，检查冲突，确认无误后才执行。

在核心引擎中，重命名采用避免相互覆盖的处理方式，执行记录可用于撤销。对不应处理的隐藏文件、符号链接、名称过长等情况也有专门的边界处理。

举个例子

从一份会议纪要识别出「星海中心」 → 选用模板「项目名 + 两位序号 + 文件类型」 → 预览得到「星海中心-01-文档.docx」「星海中心-02-演示.pptx」「星海中心-03-照片.jpg」 → 确认后执行，并下载整理后的文件包。

四、不止网页，它也能成为自动化工作流的一部分

除了浏览器入口，rnbatch 还提供命令行接口（CLI），适合脚本化处理；通过 MCP 接口，Agent 可以调用列目录、提取文本、预览改名、执行、撤销与查询历史等能力。

在这种分工里，AI 负责理解「哪些词值得用」，而重命名引擎负责「按规则准确、可检查地执行」。对整理项目资料、活动图片、设计交付文件或行政档案的人来说，这种分工更务实。

五、一个小工具，也可以认真对待每个细节

我们希望 rnbatch 是那种你第一次使用就觉得轻松、以后再遇到杂乱文件夹会自然想起的工具。它的价值不在“批量”两个字，而在于让文件管理少一些机械操作、多一些确定性。

当前 Web App 仍处于持续研发和演示验证阶段。对于上传大小、多用户隔离、长期任务持久化、不同系统 OCR 能力等，实际体验应以对应版本为准。我们会继续围绕浏览器可用性、稳定性与安全边界打磨它。

当前阶段说明：rnbatch 的主要产品方向是浏览器 Web App，目前仍在演示和安全验证阶段，并非已经完成公网多用户安全审计的成熟 SaaS。文档解析、OCR、文件数量和大小等能力随运行环境及版本而异；重要文件建议先使用副本测试，并以 当前演示版 实际功能为准。
