## I. Core Positioning

**In one sentence**: For people of different ages, professions, and capability stages, design a matrix of AI-skills-upgrade course products that is "stratified by audience, designed by scenario, and delivered by outcome" — children get creativity enlightenment, students gain learning & project capability, professionals gain efficiency, and product managers upgrade into AI product designers.

**Background judgment (key)**: In the future almost everyone needs AI capability at different levels; but different audiences need not "different-difficulty versions of the same course" but **capability systems with different goals, scenarios, and outcomes**. Therefore we don't make a single Prompt course; we make a "stratified course-product matrix."

**Market opportunity**: GitHub already has a lot of AI learning material (developers / university students / LLM / Prompt / Agent / PM directions), but mostly resource libraries or technical tutorials — what's missing is **Chinese course-product design for different audiences**. Our opportunity = reorganize public knowledge into: audience-specific learning paths + scenario-based task training + reusable Prompt / workflow templates + demonstrable outcomes + sellable / trainable / deliverable course-product packages.

## IV. Audience-specific Design Highlights

### 4.1 Children: AI Creativity Enlightenment Camp (8 parent-child lessons)
- **Goal**: AI is a tool, not magic / authority; train clear questioning; use AI to turn ideas into stories / images / characters / mini-game concepts; build privacy, true-false, dependency-risk awareness.
- **Modules**: ① What is AI → draw "my AI assistant in my mind" ② How to ask → three-question comparison card ③ Tell a story together → original fairy tale ④ Draw a character together → character design + prompt ⑤ Know the world → science question card ⑥ AI can be wrong → true-false game ⑦ My future invention → future-object design draft ⑧ Creation showcase → AI picture book / portfolio
- **Production requirements**: 30–45 min per lesson; include learning goal, intro question, interactive task, parent tip, safety reminder, after-class work; child-friendly language, no tech jargon; ≥1 hands-on task per lesson.
- **Acceptance red line**: an 8-year-old understands most of it; parent can accompany; don't encourage treating AI as authoritative answers; output leans creative not exam-oriented.

### 4.2 Middle-school: AI Learning-capability Camp (8 lessons)
- **Goal**: use AI to assist learning, not ghostwrite homework; break down hard problems; practice English / writing / speech / review; build awareness of citing sources, checking facts, avoiding plagiarism.
- **Modules**: ① AI learning-assistant intro → my rules ② ask good questions → subject-question template ③ hard-problem breakdown → mistake step-card ④ English writing → revision record ⑤ knowledge review → review plan ⑥ true-false judgment → fact-checking ⑦ speech expression → script + feedback ⑧ assistant design → user manual
- **Production requirements**: each lesson includes a learning scenario (math mistake / English essay / history material / physics concept); give "correct vs. wrong use" comparison cases; produce school / institution / family-self-study three versions.
- **Acceptance red line**: don't encourage directly copying answers; every case must require explaining understanding; must include fact-checking + academic integrity.

### 4.3 University students: AI Project & Career-capability Camp (8–10 lessons)
- **Goal**: improve learning / research / internship / job-hunt / project capability; build AI-native portfolio; go from problem → research → design → execution → showcase.
- **Modules**: ① learning & career positioning → capability map ② material research → industry report ③ paper reading → reading notes ④ data analysis → insight report ⑤ résumé interview → optimization + mock record ⑥ project design → plan ⑦ application prototype → no/low-code Demo ⑧ portfolio packaging → showcase page / collection (9–10 lessons expandable)
- **Production requirements**: each lesson includes tool list, task description, sample Prompt, evaluation criteria; ≥3 optional capstone projects (résumé-interview assistant / study-material organizer / industry-research assistant); produce portfolio template (background, problem, solution, process screenshots, screenshots, reflection).
- **Acceptance red line**: complete at least 1 demonstrable work; not stopping at Prompts, must have complete project process; work can go into résumé / interview / homepage.

### 4.4 General public: AI Work-efficiency Bootcamp (8 lessons + role packages)
- **Goal**: immediately put AI into daily work; reduce repetitive labor, raise writing / organizing / communication / analysis / decision efficiency; build one's own role AI workflow.
- **Modules**: ① tool intro → 10 high-frequency scenarios ② writing documents → notice / weekly report / proposal ③ meeting communication → minutes + follow-up ④ sales customer service → scripts / objection handling / follow-up ⑤ content operations → topics / copy / short-video ⑥ spreadsheet data → summary / business analysis ⑦ management recruitment → JD / interview questions / review ⑧ private workflow → AI assistant manual
- **Production requirements**: split material packages by role; ≥10 real scenarios per role; each scenario includes [original task / AI collaboration way / sample Prompt / output sample / human checklist / privacy-risk reminder].
- **Priority role packages**: admin / clerical, sales, customer service, operations, HR, sole proprietors.
- **Acceptance red line**: non-technical people can follow; no API / code / model parameters; emphasize "human judges, AI assists"; must include privacy + business-info protection reminders.

### 4.5 Product managers: AI Product-manager Advancement Camp (10 lessons)
- **Goal**: upgrade from "can use AI" to "can design AI products"; understand AI product vs. traditional software differences; can design AI features, RAG, Agent, evaluation metrics; can collaborate with engineering / algorithm / data / operations.
- **Modules**: ① AI product basics → capability map ② vs. traditional differences → opportunity analysis ③ Prompt & interaction → interaction plan ④ RAG / knowledge base → PRD ⑤ Agent workflow → flowchart ⑥ multimodal → feature plan ⑦ evaluation → metric system + test set ⑧ cost / latency / experience → constraint table ⑨ risk safety compliance → risk list ⑩ commercialization → complete product plan
- **Production requirements**: each lesson includes concept explanation, product case, design method, PRD template, exercise; produce 5 complete cases (AI customer service / AI enterprise knowledge base / AI résumé screening / AI content-generation workbench / AI sales assistant); each case includes [user persona / problem definition / core scenario / feature structure / Agent or RAG flow / PRD core fields / evaluation metrics / risk points].
- **Acceptance red line**: not just concepts, must produce product docs + flowcharts; must reflect AI uncertainty, evaluation, fault tolerance, human intervention; after learning can discuss implementation path with tech team.

## VII. Reusable Specs (per-lesson & Prompt-template standard)

### 7.1 Standard per-lesson structure (10 sections)
Course number / title / suitable audience / duration →
I. Course goal (knowledge / ability / work) II. Warm-up question III. Core concepts IV. Case demo (≥2–3 real scenarios) V. Hands-on task (background / input / steps / expected output) VI. Prompt template VII. Human checklist VIII. Common mistakes (3–5) IX. Homework (explicit deliverable) X. Grading rubric (completion / quality / independent thinking / usefulness).

### 7.2 Prompt-template standard structure
```
You are now playing:
My background is:
The task I want to complete is:
Target user / reader is:
Existing materials are as follows:
Please output:
Output format:
Constraints:
Please first ask me 3 key questions; if info is enough, start directly.
```
**Audience-specific complexity**
- Children: start with "I want AI to help me…"
- Middle-school: add "please guide me to understand, don't give the final answer directly"
- University: add "please give sources, analysis process, and reusable structure"
- Professionals: add "please output a version directly usable in work scenarios, with a checklist"
- PM: add "please add user scenario, feature boundary, metrics, and risk"

## IX. Risk Boundaries & Style Requirements (merged original §12 / §13)

**Risk boundaries (all courses must include)**
- AI can be wrong, don't trust blindly.
- Students must not use AI to directly ghostwrite / do papers for them.
- Professionals must not upload company secrets, customer privacy, unpublished data.
- PMs must not just show off tech, must see real user value.
- Children's use must be accompanied by parent / teacher.
- In high-risk scenarios (medical / legal / finance), AI only assists in organizing info, not replacing professional judgment.

**Unified style**: Chinese clear, direct, action-oriented; fewer terms more scenarios; one example per concept; every lesson has a deliverable; no empty popular-science; no tool manuals.
**Audience-specific style**: children = relaxed story-like encouraging expression; middle-school = clear guided emphasizing understanding; university = projectized professional demonstrable; professionals = practical direct step-by-step; PM = professional structured close to real business.
