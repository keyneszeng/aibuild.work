# 第 7 课  AI 应用原型

## 一、教学目标

- **知识**：理解"原型"是把计划书变成能演示的东西，不一定要写代码；掌握无代码/低代码路径（Coze / Dify / 飞书多维表格 / Streamlit 模板）；知道原型目的是"验证想法"不是"做产品"。
- **能力**：把一个简单 AI 助手想法，搭成一个能跑的演示（对话机器人或自动化表格）；讲清"我用了什么、怎么用"。
- **作品**：一个可演示的《无代码/低代码 AI Demo》+ 一段使用说明。

> 本课参考 LLM Universe"动手学大模型应用开发（无代码思路）"、DataTalksClub/llm-zoomcamp 的"从原型到可用"、Generative-AI-For-Beginners 的"低代码 AI 应用"章节。

## 二、开场问题

> 计划书有了，但别人说"演示看看"，你只能掏 PPT？
> 不会 Python，是不是就和"做 AI 项目"绝缘了？
> 想验证想法值不值得做，却卡在"怎么把它弄出来"？

原型不一定写代码。今天你能用拖拽工具，半小时做出一个能对话的 AI 助手。

## 三、核心概念

### 1. 原型 = 最小可演示
目标不是完美，是"让人一眼看懂你在解决什么"。一个能对话的 bot，胜过十页架构图。

### 2. 无代码路径
- **Coze / Dify**：拖拽搭一个带知识库和插件的对话机器人，零代码。
- **飞书多维表格 + AI 字段**：把表格变"智能助手"，适合资料整理类。
- **Streamlit 模板**：会一点 Python 可用现成模板改，部署快。

### 3. 该选哪条
资料问答类 → Coze/Dify 知识库；表格智能类 → 飞书多维表格；要嵌网页 → Streamlit。

### 4. 红线：别用真实隐私数据训练/上传
原型阶段用脱敏样例；涉及校内/公司真实数据，先授权。

## 四、真实场景案例演示

### 案例：课程资料问答 bot（Coze）
- 步骤：新建 bot → 上传课程笔记为知识库 → 设"只依知识库答" → 发布试聊。
- 演示：问"第三章重点"，bot 基于笔记答。
- 价值：半小时做出，验证"资料整理"需求是否成立。

## 五、动手任务

- **背景**：基于第 6 课的项目计划书。
- **输入**：计划书 MVP 范围。
- **步骤**：
  1. 选一条无代码路径。
  2. 搭出最小可演示版（含知识库或自动化）。
  3. 录屏/截图 + 写使用说明。
- **预期输出**：《AI Demo》+ 使用说明。

## 六、Prompt / 搭建模板

```
我的 MVP 是：[一句话]
目标用户试用场景：[ ]
我选的工具：[Coze/Dify/飞书多维表格/Streamlit]
请给我：①该工具的搭建步骤清单 ②知识库/数据怎么准备 ③演示时该展示的 3 个关键动作
限制：用脱敏样例，不碰真实隐私数据。
```

## 七、人工检查清单

- [ ] Demo 能真实跑通核心路径
- [ ] 未上传未授权/隐私数据
- [ ] 使用说明他人能照做
- [ ] 范围符合 MVP，没过度膨胀

## 八、常见错误

1. 一上来想做"完整产品"，迟迟做不出。
2. 用真实隐私数据训练原型。
3. 选了不匹配需求的工具。
4. 只有截图没有说明，别人看不懂。

## 九、课后作业

提交一个可演示 Demo（链接/录屏）+ 一段使用说明（≥200 字）。

## 十、评分标准

- 完成度：Demo 可运行 + 说明齐全（40%）
- 质量：路径选得对、核心路径跑通（35%）
- 安全：数据脱敏合规（25%）
