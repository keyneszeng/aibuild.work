# Lesson 10 · Portfolio Template → A Reusable Standard Showcase Framework

**Suitable for**: university students, graduate students, new graduates who need to standardize any project's showcase
**Suggested duration**: 90 minutes

## 1. Course Goals
After this lesson, you will be able to:
1. **Knowledge**: Master the five-section portfolio-card structure "background / problem definition / solution / process screenshots / results & reflection" and its filling logic;
2. **Capability**: Use a unified template to quickly package any output from Lessons 05–09 into professional, credible, horizontally-comparable project cards;
3. **Artifact**: Produce **a filled standard portfolio template** (using your real project as example), as the unified base of the portfolio (Lesson 08).

## 2. Warm-up Question
> Two students both built AI projects: one writes "I built a very impressive assistant", the other writes "background… problem… solution… screenshots… result up 40%". Who does the recruiter trust? Obviously the second.
> This lesson gives you a "fill-in-the-blank" template — just fill the boxes and your project is naturally professional.

---

## 3. Core Concepts

**1. Five sections are the minimal loop of persuasiveness**
- **Project background**: who, in what situation, why needed it (build resonance).
- **Problem definition**: specific pain point + one acceptable success criterion (without this step, the project scatters).
- **Solution**: core flow (input→process→output) + key selection reason (why this tool).
- **Process screenshots**: 2–3 real interface/output shots, proving "really built it" (no screenshot = looks unfinished).
- **Results & reflection**: quantified outcome + 1 pitfall + 1 improvement (daring to write pitfalls makes it more credible).

**2. Each box has an "anti-example red line"**
- Background not "AI is hot", but "the specific trouble I/user encountered".
- Problem definition not "a helper", but "success = achieving X".
- Screenshots not web images, must be your own real interface.

**3. Template = reusable asset**
The same five-section form fits résumé assistant, study assistant, research assistant any of them; recruiters can horizontally compare your multiple projects at a glance.

## 7. Human Review Checklist
- [ ] Background writes a specific trouble, not "AI is hot"
- [ ] Problem definition has an acceptable success criterion
- [ ] Solution clearly states flow and selection reason
- [ ] Process screenshots are your own real interface (≥2)
- [ ] Results & reflection have quantification + real pitfall + improvement

---

## 8. Common Mistakes
1. **Vague background**: writing "AI is a trend" instead of real scenario, no resonance.
2. **Unacceptable problem**: only says "build a helper", not what done looks like.
3. **Fabricated/missing screenshots**: using schematic instead of real interface, credibility to zero.
4. **Only success no pitfalls**: looks unreal, no reflection.
5. **Numbers without source**: write "up 90%" but can't say how calculated.

## Appendix: Standard Portfolio Template (with filling notes and examples)

### 【Template Structure】
```
# Project name: ________
## 1. Project Background
[Filling note] Write for "someone who doesn't know you at all". State: who, in what situation, what specific trouble encountered.
[Example] Me reviewing for finals, facing 200 pages of course PPT, don't know the key points, no direction for review.

## 2. Problem Definition
[Filling note] One-sentence pain point + one-sentence success criterion (what counts as done).
[Example] Pain point: many materials, can't grasp key points. Success criterion: input materials, produce 20 self-test questions with source page numbers within 10 minutes.

## 3. Solution
[Filling note] Core flow (input→process→output) + why this tool.
[Example] Import PDF into Feishu Multi-dimensional Tables, AI fields extract knowledge points and generate questions per paragraph, mark source page numbers. Chose it because zero-code, shareable.

## 4. Process Screenshots
[Filling note] 2~3 shots: material import interface, AI generation result, one complete output. Must be your own real interface.
[Example] (Fig1: table after PDF import; Fig2: AI fields generate questions; Fig3: one self-test question card)

## 5. Results & Reflection
[Filling note] Quantified outcome + 1 pitfall + 1 improvement.
[Example] Outcome: review time from 6 hours to 2 hours, questions cover 85% of exam points. Pitfall: v1 questions too easy, later added "grade by difficulty" Prompt. Improvement: if redo would add wrong-question review.
```

### 【Filling Red Lines】
- All numbers must be traceable; AI should not fabricate any fact for you.
- Screenshots must be real, no web schematics.
- "Success criterion" must be acceptable, else project deemed unfinished.

> 【Sources】The five-section form inherits this camp's Lesson 06 "problem definition precedes technology" and Lesson 08 portfolio-packaging paradigm.
