# Lesson 9 — Risk / Safety / Compliance

## I. Learning Goals

- **Knowledge**: Understand the unique risks of AI products — hallucination, bias, privacy, compliance, loss of control; master the design method of "risk list + human fallback."
- **Ability**: List a risk list for an AI product and give a countermeasure for each item (especially the human fallback).
- **Artifact**: An *AI Product Risk List* (for pre-launch review).

> This lesson references microsoft/AI-For-Beginners' AI ethics chapter, deanpeters' compliance considerations, and Generative-AI-For-Beginners' Responsible AI.

## II. Warm-up Question

> The AI confidently makes up a policy, an employee follows it — who's responsible?
> The model uses different tones for two types of users — is that discrimination?
> User data goes into model training — is that compliant?

AI's risk is "looks right, actually wrong." The PM must list them and plug the holes.

## III. Core Concepts

### 1. The Five Major Risks
- Hallucination: fabricating facts
- Bias: output carries discrimination / unfairness
- Privacy: leaking personal / business data
- Compliance: violating industry regulation (finance / medical / content)
- Loss of control: Agent acts beyond authorization

### 2. Countermeasure Matrix
Each risk → prevention (prompt / permissions) + detection (evaluation / monitoring) + fallback (escalate to human / roll back).

### 3. Human Fallback
Before high-risk output (advice / commitment / external), set human confirmation; this is the bottom line.

### 4. Compliance Boundary
In heavily regulated domains (medical / legal / finance), AI only assists and a licensed person must stand guard.

## IV. Worked Example (Real Product Scenario)

### Case: Risk List for a Financial Q&A Product
- Hallucination: answers the wrong interest rate → countermeasure: RAG only from official docs + label "subject to the contract"
- Compliance: gives investment advice → countermeasure: add disclaimer + don't make decisions on behalf of the client
- Privacy: asks "my account" → countermeasure: identity verification + don't enter training

## V. Hands-on Task

- **Background**: List risks for your AI product.
- **Input**: feature and user group.
- **Steps**:
  1. List ≥ 5 risks (hallucination / bias / privacy / compliance / loss of control).
  2. For each, write prevention + detection + fallback.
  3. Mark the nodes "requiring human confirmation."
- **Expected output**: *AI Product Risk List*.

## VI. Prompt / Design Template

```
Feature: [ ] Domain: [ ]
Please output a risk list: for each item list [risk / impact / preventive measure / detection method / fallback plan], and mark the nodes requiring human confirmation.
```

## VII. Human Review Checklist

- [ ] Covers the five major risk categories
- [ ] Each item has prevention + detection + fallback
- [ ] Human-confirmation nodes are clear
- [ ] Regulated domains have compliance design

## VIII. Common Mistakes

1. Only writes "pay attention to safety" with no specifics.
2. Has risks but no fallback.
3. In regulated domains, lets AI decide directly.

## IX. Homework (Deliverables)

Submit one *AI Product Risk List*.

## X. Grading Rubric

- Completion: list complete (40%)
- Quality: each item has a countermeasure (35%)
- Bottom line: human-confirmation nodes are clear (25%)
