# Lesson 7 — Evaluation System

## I. Learning Goals

- **Knowledge**: Understand that an AI product must be "evaluable" — because models err and drift; master the core evaluation dimensions (accuracy / relevance / safety / experience) and test-set design.
- **Ability**: Design an evaluation-metrics table + test-set approach for an AI feature (connects to the Lesson 13 evaluation-metrics table).
- **Artifact**: An *AI Evaluation Plan* (metrics + test set + acceptance thresholds).

> This lesson references deanpeters' Measure-stage skills, mlabonne/llm-course's Evaluation, and DataTalksClub/llm-zoomcamp's evaluation and monitoring.

## II. Warm-up Question

> Before launch, how do you prove "this AI answers decently"?
> Users complain "it's getting dumber" — what do you quantify with?
> The model gets upgraded — will the old, working behavior break?

An AI product without evaluation is flying blind.

## III. Core Concepts

### 1. Four-Dimension Evaluation
- Accuracy: is the answer correct (fact-based)
- Relevance: is the answer what the user asked
- Safety: any harmful / violating output
- Experience: smoothness, tone, sense of speed

### 2. Test Set
Prepare a batch of "standard questions + standard answers / scoring rules," run it after every change, and watch the score move. This is regression testing.

### 3. Human Evaluation
When machine scores aren't enough, sample and have humans score (especially the safety / experience dimensions).

### 4. Continuous Monitoring
After launch, instrument "thumbs up / down / escalate-to-human rate" to detect degradation and roll back in time.

## IV. Worked Example (Real Product Scenario)

### Case: Customer-Service Bot Evaluation
- Test set: 100 real Q&A pairs, labeled "should answer / shouldn't answer / answer correctly without fabricating."
- Metrics: knowledge-base correct-answer rate ≥ 90%, fabrication rate ≤ 1%, escalate-to-human rate monitored.
- Regression: re-run after every prompt change; only ship if the score doesn't drop.

## V. Hands-on Task

- **Background**: Set evaluation for your AI feature.
- **Input**: feature definition.
- **Steps**:
  1. Pick 3–4 evaluation dimensions.
  2. Design the test-set structure (questions + scoring).
  3. Set acceptance thresholds and monitoring metrics.
- **Expected output**: *AI Evaluation Plan*.

## VI. Prompt / Design Template

```
Feature: [ ]
Please design an evaluation plan: ① core dimensions (pick applicable from accuracy / relevance / safety / experience) ② how to build the test set (volume / source / labeling) ③ acceptance threshold for each dimension ④ which signals to monitor after launch.
```

## VII. Human Review Checklist

- [ ] Dimensions cover at least accuracy / safety
- [ ] Test set has a real source
- [ ] Has acceptance thresholds and a regression mechanism
- [ ] Online monitoring signals are clear

## VIII. Common Mistakes

1. Only test "does it work" not "is it good."
2. No test set, relying on feeling.
3. No monitoring after launch — only notice degradation later.

## IX. Homework (Deliverables)

Submit one *AI Evaluation Plan*.

## X. Grading Rubric

- Completion: plan complete (40%)
- Quality: dimensions reasonable, thresholds present (35%)
- Continuity: monitoring and regression in place (25%)
