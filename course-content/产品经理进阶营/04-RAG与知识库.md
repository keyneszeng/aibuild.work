# 第 4 课  RAG 与知识库

## 一、教学目标

- **知识**：理解检索增强生成（RAG）的原理与适用场景——让模型"基于你给的资料答"，而非凭记忆编；掌握知识库产品的设计要点（切片、检索、兜底）。
- **能力**：为"企业知识库问答"类需求设计 PRD（含知识来源、检索策略、兜底逻辑）。
- **作品**：一份《知识库产品 PRD》（参照 deanpeters 的 prd skill 结构）。

> 本课参考 DataTalksClub/llm-zoomcamp（RAG/向量检索实战）、datawhalechina/llm-universe（搭知识库）、Generative-AI-For-Beginners 的 RAG 章节。

## 二、开场问题

> 让员工问 AI"公司报销政策"，它却编一条假的？
> 模型训练数据里没有你公司资料，它怎么可能答对？
> 怎么让 AI"只依据我们内部文档答"？

RAG 就是答案：先检索你的资料，再让模型基于资料生成。模型变"有依据"。

## 三、核心概念

### 1. RAG 三段
检索（从知识库找相关片段）→ 增强（把片段塞进提示）→ 生成（模型基于片段答）。核心是"给证据再答"。

### 2. 知识库设计要点
- 切片：文档怎么切（按章节/固定长度），影响检索质量。
- 检索：用向量相似度找最相关片段。
- 兜底："资料没有就如实说，不编"（红线）。

### 3. 适用场景
企业内部问答、客服知识库、法规/制度查询——凡"答案必须在指定资料里"的，都适合 RAG。

### 4. 评估
检索准不准、答得依不依据资料，需测试集（见第 7 课）。

## 四、真实产品场景案例演示

### 案例：HR 政策问答 bot
- 知识源：员工手册 PDF。
- 流程：问"年假怎么算"→ 检索手册相关段 → 模型基于该段答。
- 兜底：手册无此条 → "建议联系 HR 确认"。
**价值**：零编造，可信赖。

## 五、动手任务

- **背景**：设计一款企业知识库问答产品。
- **输入**：知识源类型（文档/FAQ）。
- **步骤**：
  1. 用"PRD 模板"写问题/指标/范围。
  2. 设计检索与兜底逻辑。
  3. 列评估维度。
- **预期输出**：《知识库产品 PRD》。

## 六、Prompt / 设计模板

```
你是 AI 产品 PM，写一份知识库问答 PRD，含：
【问题/目标用户/核心场景/知识源/检索策略/兜底逻辑/成功指标/范围边界】。
参考 RAG 思路：模型只依检索到的资料答，无资料则转人工。
```

## 七、人工检查清单

- [ ] 知识源与切片策略明确
- [ ] 兜底（不编造）逻辑到位
- [ ] 有检索质量评估方案
- [ ] 范围边界清晰

## 八、常见错误

1. 没兜底，模型自由发挥编政策。
2. 切片粗糙导致检索不到。
3. 无评估，答得对不对不知道。

## 九、课后作业

提交《知识库产品 PRD》一份。

## 十、评分标准

- 完成度：PRD 要素齐全（40%）
- 质量：RAG 逻辑正确、兜底明确（35%）
- 可测：评估方案合理（25%）
