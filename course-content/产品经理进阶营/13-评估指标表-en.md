# 13 · AI Product Evaluation Metrics Table

> An AI product can't go live just because it "feels about right." This table is the PM's general tool for aligning with algorithm/data on "what counts as success." It is divided into four categories: **effect, experience, cost, safety**.

## II. Offline Eval-Set Construction Spec

A trustworthy eval set is the AI product's "regression test." Construction points:

1. **Scale**: start with at least 100–300 items, covering the real distribution.
2. **Stratification**: stratified sampling by intent/scenario, including high-frequency, long-tail, edge, and adversarial samples.
3. **Golden answer**: label expected output or acceptance criteria per item (Given/When/Then works).
4. **Difficulty tags**: easy / medium / hard / trap (easily triggers hallucination).
5. **Versioning**: the eval set grows with product iteration; run full regression on every model/Prompt change.

## III. Online Evaluation Methods

- **Shadow mode**: the new model runs online but is invisible to users, compared against old results.
- **Canary / A-B**: roll out by ratio, compare core metrics (success rate, cost, satisfaction).
- **Red-line circuit breaker**: if any red-line metric (e.g., hallucination rate, leak rate) exceeds threshold, auto-roll-back.

## IV. Metric-Use Discipline

- **Don't look at a single metric**: high success rate but exploding cost, or low latency but high hallucination — neither can launch.
- **Separate offline / online**: passing the offline eval set ≠ good online performance; canary validation is mandatory.
- **Red lines first**: safety metrics are veto items, not traded against effect metrics.
