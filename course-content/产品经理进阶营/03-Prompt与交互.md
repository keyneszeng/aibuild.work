# 第 3 课  Prompt 与交互

## 一、教学目标

- **知识**：理解"Prompt 设计"本质是 AI 产品的交互设计——它决定用户怎么和模型对话；掌握角色设定、多轮澄清、约束输出、few-shot 等核心手法。
- **能力**：为一款 AI 功能设计交互方案（含系统提示词骨架、澄清逻辑、输出约束）。
- **作品**：一份《AI 交互方案》（含角色设定 + 澄清流程 + 输出格式约束）。

> 本课参考 dair-ai/Prompt-Engineering-Guide（角色扮演/结构化输出/澄清/few-shot）、datawhalechina/easy-vibe 的"交互即产品"思路。

## 二、开场问题

> 用户一句"帮我写点东西"，AI 怎么知道写啥？
> 为什么有的 AI 一问到底，有的答非所问？
> 输出格式乱七八糟，前端怎么展示？

Prompt 不是"给模型的咒语"，是产品交互的第一道设计。

## 三、核心概念

### 1. 角色设定（System Prompt）
给模型一个稳定身份与边界："你是 XX 助手，只做 Y，超出范围礼貌拒绝"。这等于产品的"人设 + Scope"。

### 2. 多轮澄清
用户意图模糊时，模型应先问关键问题再动手（参考第 10 课通用模板）。产品上要设计"澄清话术"而非硬猜。

### 3. 结构化输出
要求模型按固定格式（JSON/表格/三段）输出，前端才好渲染。这是 Prompt-Engineering-Guide 强调的"明确输出格式"。

### 4. few-shot：用样例定风格
给 1–3 个示例，模型模仿语气与结构。适合品牌调性统一的场景。

## 四、真实产品场景案例演示

### 案例：AI 简历改写助手的交互
- System："你是求职教练，只做简历优化，不编经历。"
- 澄清："请先给我你的原简历和目标岗位。"
- 输出：严格 STAR 三段 + [真实数据]占位。
**价值**：交互即约束，减少废话与造假。

## 五、动手任务

- **背景**：为一款你设计的 AI 功能写交互。
- **输入**：功能定位。
- **步骤**：
  1. 写 System Prompt（人设+边界）。
  2. 设计 2 个澄清问题逻辑。
  3. 定义输出格式约束。
- **预期输出**：《AI 交互方案》。

## 六、Prompt / 设计模板

```
System：你是[角色]，职责[ ]，不做[边界]。
当用户意图不清时，先问：[问题1][问题2]。
输出格式严格为：[格式]。
如领域外，回复："这个我帮不上，建议[ ]"。
```

## 七、人工检查清单

- [ ] 人设与边界清晰
- [ ] 有澄清机制而非硬猜
- [ ] 输出格式前端可渲染
- [ ] 越界有优雅拒绝

## 八、常见错误

1. System Prompt 太泛，模型乱答。
2. 不澄清直接生成，废话多。
3. 输出无格式，前端无法用。

## 九、课后作业

提交《AI 交互方案》，含 System + 澄清 + 输出约束。

## 十、评分标准

- 完成度：方案齐全（40%）
- 质量：边界/澄清/格式合理（35%）
- 体验：越界处理优雅（25%）
