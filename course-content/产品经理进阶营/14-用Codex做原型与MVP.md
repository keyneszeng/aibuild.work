# 第 14 课  用 Codex 做原型与 MVP —— 产品经理不写代码，也能把想法跑起来

## 一、教学目标

- **知识**：理解 Codex 作为"编码智能体"对产品经理的价值——它把"想法到可点原型"的距离压缩到小时级；分清 App / CLI / IDE / Web 四种形态。
- **能力**：用产品语言给 Codex 下需求，独立产出可演示的网页原型 / 小工具 MVP，并用红蓝线评估其可用性。
- **作品**：一个能打开就用的《我的产品原型 v0.1》（网页或小程序形态）+ 一份《Codex 产出评估清单》。

## 二、开场问题

> 你有没有过这种时刻：脑子里有个功能点子，画了原型图，但找不到开发排期，idea 就一直停在 Figma 里？
> 这节课，你用 Codex 自己把它跑起来——**不用等研发，下午就能给老板演示**。

## 三、核心概念

### 1. Codex 是什么（产品视角版）

Codex 是 OpenAI 的**编码智能体**：你说"我要一个能 XX 的网页/工具"，它自己写前端、后端、建文件、跑起来。
对产品经理的意义——**它是你的"影子研发"**，把验证成本从"排期两周"降到"下午搞定"。

橙皮书梳理的四种形态：

| 形态 | 入口 | 产品岗用法 |
|---|---|---|
| **Codex App（桌面）** | 装软件选文件夹 | ⭐ 最推荐，功能最全、最顺手 |
| **Codex CLI** | 终端 | 进阶、爱折腾 |
| **Codex IDE 扩展** | VS Code / Cursor | 和研发协作时 |
| **Codex Web（云端）** | chatgpt.com/codex | 不想装软件 |

### 2. 产品岗 vs 研发岗用 Codex 的差异

- 研发：用 Codex 写生产代码、修 bug、接 API。
- 产品：用 Codex **验证想法、做可点原型、生成竞品 demo、自动化重复分析**——目的不是"代码质量"，是"快速看见东西"。

### 3. 三种能立刻用的姿势（橙皮书精要）

- **对话式**：聊着聊着把原型做出来，适合探索阶段。
- **单次任务**：一句指令出结果，如"做个登录页 HTML"。
- **文件夹工作模式**：把一个项目目录交给它，统一改样式/加页面——做多页原型的主战场。

### 4. 产品心法：用"用户故事 + 界面要求"下指令

别说"做个 CRM"。要说：
> "做一个单页 Web：顶部标题'客户跟进'，中间一个表单（客户名/需求/优先级下拉），提交后下面列表实时显示，数据存浏览器本地。风格简洁、移动端可用。"

**把"给谁用、有哪些字段、长什么样、数据怎么存"一次说清**，它做出的就接近可演示。

## 四、真实场景案例（摘自橙皮书实战思路）

### 案例 1：宠物零食售卖页（橙皮书案例一原型）
**做法**：让 Codex "做一个宠物零食售卖前端页，含商品卡、加购按钮、结算区"。
**产品收获**：1 小时拿到可点页面，直接拿去和用户聊，比静态图反馈真实 10 倍。

### 案例 2：管理后台（案例三）
**做法**：在前面页面基础上，"加一个管理后台，能增删商品、看订单"。
**产品收获**：验证"后台复杂度是否在 MVP 范围"——Codex 跑出来的坑，就是你要和研发对齐的需求边界。

### 案例 3：招商 PPT + 宣传视频（案例四、五）
**做法**：让 Codex 配合多模态工具产出 PPT 和视频素材。
**产品收获**：融资/立项材料当天出初稿。

## 五、标准工作流（产品 MVP 版，5 步）

1. **写用户故事**：谁、在什么场景、要解决什么。
2. **定 MVP 边界**：只做最核心 1 条主路径，砍掉所有"以后再说"。
3. **下指令生成**：用上面的"用户故事 + 界面要求"句式，一次生成。
4. **人审 + 红蓝线评估**（见第七节）：自己点一遍，列"能用 / 不能用 / 要研发接手"。
5. **迭代 / 移交**：小修让 Codex 继续；涉及生产代码、数据安全，交给研发。

## 六、Codex 产出的评估清单（产品用）

| 维度 | 自问 |
|---|---|
| 功能可用 | 主路径能跑通吗？边界情况崩不崩？ |
| 数据安全 | 有没有把用户数据传外网？是否该转本地/研发？ |
| 代码可交接 | 生成的东西研发接手改得了吗？（要求它留注释/结构清晰） |
| 成本 | 跑一次花多少额度？值不值？ |
| 合规 | 涉及隐私/金融/医疗，是否踩红线？ |

## 七、红线总提醒（务必遵守）

- 不把**公司涉密源码、客户 PII、未公开数据、密钥/Token** 喂给 Codex 或任何 AI。
- AI 生成代码**可能出错、可能有安全漏洞**：人来判断、AI 辅助；涉及生产环境、真实用户数据，必须交研发审核。
- 先在**副本/测试项目**里跑，确认安全再碰真数据。
- Codex 更新很快（安装、模型名、入口、额度都可能变），以 OpenAI 官方文档和账号实际显示为准。
- 用 Codex 出的原型**只用于内部验证**，对外发布前需走正常研发+安全流程。

## 八、课后小任务

挑你手头一个**排期遥遥无期的功能点子**，用 Codex App 做一个能点开的 v0.1 原型，并填好上面的《评估清单》——这就是你下次评审会最硬的底气。
