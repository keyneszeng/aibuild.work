# Lesson 10 — Commercialization & Launch

## I. Learning Goals

- **Knowledge**: Understand that what's missing between an AI product "can run" and "can sell" is commercialization design — pricing, target customers, channels, value proof, ROI; be able to integrate the methodologies of the first 9 lessons into one complete product plan.
- **Ability**: Design a commercialization path for an AI product, producing a complete plan that includes user persona, problem, scenario, feature structure, RAG/Agent flow, core PRD fields, evaluation metrics, and risk points.
- **Artifact**: A *Complete AI Product Plan* (can be presented to investors / boss / technical team).

> This lesson integrates the first 9 lessons (basics / differences / Prompt / RAG / Agent / multimodality / evaluation / cost / risk), referencing deanpeters' Deliver+Measure stages and product-on-purpose/pm-skills' commercialization framework.

## II. Warm-up Question

> The feature is built, the boss asks "how much money can this make" — can you answer?
> Same AI assistant, sold to individuals vs sold to enterprises — why are the approaches completely different?
> How do you prove to engineering that "this is worth doing"?

Commercialization isn't "add a paywall button" — it's turning value into a measurable business.

## III. Core Concepts

### 1. Value Proof (ROI)
The selling point of an AI product must be "how much money saved / how much money earned / how much time saved." Reverse-engineer from the cost perspective of Lesson 8: the cost you help the user cut is the money you can charge.

### 2. Customers & Pricing
- To C: low unit price, relies on scale, experience-sensitive.
- To B: high unit price, relies on value proof, needs POC (proof of concept) and contracts.
- Pricing models: subscription / usage-based / tiered value-add.

### 3. The Eight Elements of a Complete Plan
User persona → problem definition → core scenarios → feature structure → RAG/Agent flow → core PRD fields → evaluation metrics → risk points. Each of the first 9 lessons contributes one block.

### 4. Launch & Iterate
Use Lesson 7 evaluation + Lesson 9 risk for launch review; use the data flywheel (Lesson 2) for continuous iteration.

## IV. Worked Example (Real Product Scenario)

### Case: AI Enterprise Knowledge Base (integrated plan)
- User persona: HR/Admin at SMBs under 200 people, no dedicated IT.
- Problem: employees repeatedly ask policy questions, HR buried in trivia.
- Scenario: annual-leave / reimbursement / onboarding Q&A.
- Feature: RAG Q&A bot + back-end knowledge management.
- Flow: retrieve handbook → answer based on passage → escalate to human if no material (Lesson 4).
- PRD fields: knowledge source, retrieval strategy, fallback, permissions (Lessons 4/5).
- Evaluation: correct-answer rate ≥ 90%, fabrication rate ≤ 1% (Lesson 7).
- Risk: privacy leak, policy fabrication (Lesson 9).
- Commercialization: per-seat subscription, ROI = HR saving 30% of Q&A time.

## VI. Prompt / Design Template

Please output a complete plan: ① user persona (with confidence) ② problem definition ③ 3 core scenarios ④ feature structure ⑤ RAG or Agent flow ⑥ core PRD fields ⑦ evaluation metrics (with thresholds) ⑧ risk points and fallback ⑨ commercialization: customers + pricing + ROI argument.

## VII. Human Review Checklist

- [ ] The eight elements are complete and mutually aligned
- [ ] ROI has a quantified basis
- [ ] Pricing matches the customer segment
- [ ] Evaluation and risk are closed-loop

## VIII. Common Mistakes

1. The plan's blocks from each lesson are incoherent and contradictory.
2. Talks features but not money.
3. ROI made up with no basis.
4. Evaluation / risk vanish from the plan.
