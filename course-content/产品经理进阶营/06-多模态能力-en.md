# Lesson 6 — Multimodal Capabilities

## I. Learning Goals

- **Knowledge**: Understand where multimodality (text / image / speech / video) lands in an AI product; know which scenarios are "impossible without multimodality."
- **Ability**: Design a multimodal plan for a product feature (choose modality, define input/output, think about boundaries).
- **Artifact**: A *Multimodal Feature Plan*.

> This lesson references microsoft/AI-For-Beginners (CV/NLP/multimodality chapters), Generative-AI-For-Beginners (multimodal applications), and mlabonne/llm-course's technical-boundary notes.

## II. Warm-up Question

> A user snaps a photo and you should be able to answer — a pure-text product can't do that, right?
> Why does a voice assistant sometimes not understand a dialect?
> Video generation is cool, but does your product really need it?

Multimodality isn't a checklist of flashy tricks — it's that "the user's real input is naturally an image / sound / video."

## III. Core Concepts

### 1. Modality = Input/Output Form
Text, image, speech, video. The product should choose "whatever the user naturally uses, you accept that."

### 2. Typical Landing Points
- Image: photo Q&A, OCR, recognition (e-commerce / medical / industrial)
- Speech: voice assistant, transcription, real-time captions
- Video: generate spoken clips, analyze surveillance

### 3. Cost vs Experience Trade-off
Multimodality is more expensive and slower (see Lesson 8). Don't use it unless necessary.

### 4. Red Line: Privacy & Compliance
Cameras / microphones involve strong privacy — explicit authorization and notice are required.

## IV. Worked Example (Real Product Scenario)

### Case: E-commerce "Snap to Find Similar"
- Input: user photographs a product.
- Processing: image retrieval + text-generated description.
- Output: list of similar products.
**Value**: the user's natural input is an image; text search would be awkward instead.

## V. Hands-on Task

- **Background**: Choose a modality for a feature.
- **Input**: user scenario.
- **Steps**:
  1. Judge the primary modality (image / speech / video / text).
  2. Design the input/output flow.
  3. List privacy and cost considerations.
- **Expected output**: *Multimodal Feature Plan*.

## VI. Prompt / Design Template

```
Scenario: [how the user naturally inputs]
Please help me design a multimodal plan: ① primary modality and rationale ② input → processing → output flow ③ required capabilities (recognition / generation) ④ privacy and cost considerations.
```

## VII. Human Review Checklist

- [ ] Modality choice fits the user's real input
- [ ] Privacy-authorization mechanism is clear
- [ ] Multimodality isn't overused when unnecessary

## VIII. Common Mistakes

1. Forcing video generation just to show off.
2. Camera scenarios without authorization notice.
3. Ignoring multimodal cost.

## IX. Homework (Deliverables)

Submit one *Multimodal Feature Plan*.

## X. Grading Rubric

- Completion: plan complete (40%)
- Quality: modality fits, flow is clear (35%)
- Compliance: privacy and cost considered (25%)
