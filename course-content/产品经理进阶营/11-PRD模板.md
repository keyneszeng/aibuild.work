# 11 · AI 产品 PRD 模板

> 本模板在标准 PRD 基础上，强化了"AI 专有字段"。直接复制使用，括号内为填写指引。

---

## 0. 文档元信息
- 产品 / 功能名称：
- 版本：v0.1（PRD 草稿）
- 作者 / 日期：
- 状态：🟡 评审中 / 🟢 已批准 / 🔴 已打回
- 相关材料：需求来源、用户访谈记录、竞品分析链接

## 1. 背景与问题（Why）
- **用户痛点**：（谁，在什么场景下，遇到了什么问题，现状方案为何不够）
- **机会来源**：数据 / 访谈 / 竞品 / 战略
- **成功标准初判**：（用一句话描述"做成什么样算赢"）

## 2. 目标用户与画像（Who）
- 核心用户画像：（角色、目标、痛点、当前 workaround）
- 边缘用户 / 反对者：（谁会抵制或被影响）
- 使用频次与场景：高高高频 / 偶发 / 嵌入式

## 3. 目标与指标（Metrics）——AI 必须量化
| 指标 | 定义 | 目标值 | 数据来源 | 责任人 |
|---|---|---|---|---|
| 任务成功率 | 用户目标达成比例 | ≥ 90% | 埋点 | |
| 首响准确率 / 命中率 | 答案命中用户意图的比例 | ≥ 85% | 人工标注 | |
| 幻觉率 | 出现事实性错误的比例 | ≤ 3% | 评测集 | |
| 人工介入率 | 需转人工 / 人工复核比例 | ≤ 15% | 日志 | |
| 平均延迟 P95 | 端到端响应耗时（95 分位） | ≤ 3s | APM | |
| 单任务成本 | 单次调用 Token / 费用 | ≤ ¥0.05 | 账单 | |

## 4. 方案概述（What）
- **核心交互流程**：（一句话 + 流程图引用，见 12-Agent 工作流模板）
- **是否用到 AI**：☐ 纯规则 ☐ RAG ☐ Agent ☐ 多模态 ☐ 混合
- **AI 能力边界**（明确不做什么）：

## 5. AI 方案细节（AI-Specific）
### 5.1 模型与链路
- 模型选型：（大模型 / 小模型 / 自研，原因）
- 是否 RAG：（知识源、更新频率、切分策略）
- 是否 Agent：（有哪些工具 / 子任务，见 12）
- 上下文工程：（系统提示、记忆机制、长期记忆 vs 会话记忆）

### 5.2 不确定性与容错设计（红线）
- **幻觉应对**：置信度阈值、引用溯源、低置信转人工
- **失败兜底**：超时 / 拒答 / 错误格式的处理路径
- **人工介入点**：哪些环节必须人审（如高风险决策、对外承诺）
- **可解释性**：用户能否看到"依据什么给出的回答"

### 5.3 评估与测试集（见 13）
- 离线评测集：规模、构造方式、标注规范
- 在线评估：影子模式 / A-B / 灰度比例
- 红线指标：不可接受的失败类型清单

## 6. 功能需求（Stories）
- 作为【用户】，我希望【能力】，以便【价值】
- 验收标准（Given/When/Then）：
- 边缘情况（edge cases）：错误输入、超长文本、越权、空结果

## 7. 非功能约束（约束表见 08）
- 延迟、成本、并发、合规、数据驻留、隐私脱敏

## 8. 风险与合规（清单见 09）
- 法律风险、安全风险、品牌风险、依赖风险
- 合规要求：（个保法、行业监管、内容审核）

## 9. 上线与放量计划
- 灰度策略：内部 → 种子用户 → 全量
- 回滚条件：（触发即回滚的红线指标）
- 监控看板：哪些指标每日看

## 10. 协作分工（Who builds）
| 角色 | 责任 | 交接物 |
|---|---|---|
| 产品 | 需求 / 指标 / 验收 | 本 PRD |
| 算法 | 模型 / 评测集 / 调优 | 评测报告 |
| 工程 | 链路 / 工程化 / 监控 | 上线 | 
| 数据 | 知识库 / 标注 | 数据集 |
| 运营 | 话术 / 用户教育 / 反馈回收 | 运营 SOP |
