# Lesson 8 · Personal Workflow → Your Personal AI Assistant Spec

## I. Learning Goals

- **Knowledge**: Understand that a "workflow" is not buying a tool, but hardening what you repeatedly do into "steps + templates + checkpoints"; master the method of "stringing the templates from the previous 7 lessons into one line."
- **Skill**: Write your own *Personal AI Assistant Spec* — clearly stating "who I am, what I often do, which template for each task, where I must gate it."
- **Output**: A reusable *Personal AI Assistant Spec* (with scenario → template → red-line mapping).

> This lesson integrates the previous 7 lessons' methodology, referencing LLM-Universe's "harden capability into reusable process" and Generative-AI-For-Beginners' "embed AI into daily tasks" ideas.

## II. Warm-up Question

> Learned a pile of AI tricks, but next week you still improvise "how should I ask" when something comes up?
> On your team, if a different person takes over, nobody knows "how do we use AI for this"?
> Want to turn your own AI experience into a process that "runs without thinking"?

A personal workflow is writing down "your way of using it," turning AI into a co-pilot that's there whenever you call.

## III. Core Concepts

### 1. Workflow = scenario × template × red line
For each high-frequency scenario, pair a fixed template and mark one "human-gate point." Only with all three does it become a process.

### 2. The spec is written for "future you"
State clearly: who am I, what are my high-frequency scenarios, which template does each scenario call, and which items do I check after output.

### 3. Continuous iteration: change it every time you use it
Whenever AI answers wrong, reverse-engineer it — fix the template or add a checklist item. The spec is alive.

### 4. Red-line principle: human judges, AI assists
Price / policy / privacy / high-risk decisions are always mine; AI only drafts.

## IV. Real Work Scenario Demo

### Case: String "weekly report + client follow-up + data" into a Monday routine
**Spec excerpt**: "Monday 9:00 → use the 'Weekly Report Template' to summarize last week → use the 'Follow-up Template' to generate the client list → use the 'Data Template' for insights → run all three through the 'Human Review Checklist' before sending."
**Value**: No need to think each time — just follow the flow.

## V. Hands-on Task

- **Background**: Review all the templates and checklists you produced in the previous 7 lessons.
- **Input**: Your own role and high-frequency scenarios.
- **Steps**:
  1. List your 5–8 most-used work scenarios.
  2. Bind a template to each scenario (reference earlier files).
  3. Mark 1–2 "I must gate this" points for each scenario.
  4. Write it up as a spec.
- **Expected output**: *Personal AI Assistant Spec*.

## VI. Prompt Template (Spec Skeleton)

```
My role: [position]
My high-frequency scenarios: [list 5–8]
For each scenario, the template and gate point:
- Scenario 1 → use [template name] → I check [checklist item]
- Scenario 2 → …
Overall red lines: [human judges, AI assists; no privacy leakage; no making commitments on my behalf]
```

## VII. Human Review Checklist

- [ ] Scenarios cover 80% of my repetitive work
- [ ] Every scenario has a corresponding template
- [ ] Every scenario marks a gate point
- [ ] Red lines are clear and actionable

## VIII. Common Mistakes

1. The spec is too vague — "use AI more" with no concrete scenario.
2. Lists only tools, not templates — still don't know how at a new scenario.
3. Omits gate points, equal to no defense at all.

## IX. Homework

Submit a *Personal AI Assistant Spec* with ≥5 scenarios, each with a template and a gate point.

## X. Grading Rubric

- Completion: spec complete (40%)
- Quality: real scenarios, templates referenceable (35%)
- Safety: gate points and red lines explicit (25%)
